## Risks for the next phase

1. **The first CI run should fail in `integration`.** The job runs `pnpm run test:acceptance` with no site build, and `@d2rmm/acceptance` does not depend on `@d2rmm/web`, so turbo's `^build` skips it. This comes from reading `ci.yml` and `turbo.json`, and the same error reproduced locally: 100 scenarios failed on a checkout with no `apps/web/dist`. Fix proposed in `brief-revision-3.md`.
2. **None of this code has run on GitHub or on Windows.** 506 commits have only run on this Mac, with Windows clippy in a container (AD-071). Expect more first-run failures in the workflows, secrets and the Windows `agent` job. Windows adapters were judged by reading only.
3. **The agent mutation metric cannot populate.** `cargo mutants --output reports/mutation/agent-core` writes `agent-core/mutants.out/outcomes.json`, and the baseline reads `agent-core/outcomes.json`. Confirmed at this run: the first file exists and the ratchet still says "not measured". The nightly has a second gap: `agent-mutation` runs in its own Windows job and the `quality` job, which runs the ratchet, never downloads its report. The ratchet guards nothing for the agent until both are fixed.
4. **The review step fails by construction.** As above, `validate_verification.py` on the phase head always fails and spends budget. The fix belongs in the phase-runner skill, since the TLC script is vendored; otherwise the next phase's review burns the same budget.
5. **`test:e2e` is empty.** No workspace defines it, so the CI step has nothing to run. Playwright coverage comes from acceptance.
6. **API domain mutation has almost no margin.** 98.06 against a floor of 98.00 (baseline 100, tolerance 2%). A small drop in F1 would fail the phase ratchet.
7. **The nightly is unhealthy on `main`.** Run `41653012528` failed its `quality` job at "Harness report" (cause not read), and `backup` waits for a reviewer on every run, so scheduled runs pile up. Decide whether the backup should need a reviewer at all.
8. **Telemetry and egress must come down before real players:** split the sink's count by signal first, then restore the failing rule.
9. **Local acceptance has unwritten prerequisites.** A fresh checkout needs `pnpm build` and the headless example built first, or the run fails or starves itself. The rejection at `support/world.ts:259` appeared under that load and did not recur in the clean run.
10. **Budget on read-only steps.** A step that only reads, like this validator, can block a finished feature. Worth reviewing whether it should spend budget.
