# ADR 024 — Deterministic phase state and idempotent resume

**Status**: Accepted
**Date**: 2026-10-30
**Deciders**: maintainer

## Context

Five phases (F0–F4) will run over many agent sessions, compactions, worktrees and possibly machines. If "where we
are" lives in an agent's memory or in a status table it edits by hand, a resumed session can redo finished work,
skip a step, or trust a stale note. External boards (Jira) were considered and dropped: the repository itself must
hold the state.

## Decision

1. **State is derived, not remembered.** `scripts/phase-status.mjs` computes the phase's next step and each
   feature's next step (`specify → spec-gate → design → tasks → tasks-gate → execute → proofs → verify → integrate
→ done`) from evidence only: files in `.specs/`, approval lines, git commit trailers and the retry ledger. Every
   runner step starts from `phase-status --json`; the brief's `## Runner state` is regenerated by `--write`.
2. **Progress is recorded in git history.** Every commit on `feat/F<n>-<feature>` carries `Feature: <feature>` and
   `Task: T<n>` (a task declared in `tasks.md`) or `Step: spec|design|tasks|proofs|verification|integration|fix`,
   enforced by the commit-msg hook. A feature is integrated when its `Step: verification` commit is reachable from
   `phase/<F>`.
3. **Budgets survive clones.** `phase-status --write` commits a snapshot of the retry ledger
   (`.specs/phases/<F>/attempts.json`); loading merges it with the live ledger and never loosens (blocked wins,
   more failures win; only a newer maintainer reset clears a unit). Agents cannot edit the snapshot.
4. **The five phases are complete by construction.** `ROADMAP.md` assigns every PRD requirement to exactly one
   primary phase; `pnpm specs:check` fails when a requirement has none or several, and when an approved brief does
   not cover its phase's requirements.
5. **Phase lifecycle**: `kickoff → awaiting-approval → run → review → awaiting-review → merge → closed`. The next
   kickoff refuses to start until the previous phase is `closed` (review approved and `phase/<F>` merged into `main`),
   and its first step tightens the quality baseline with the merged numbers.

## Alternatives considered

- Jira or another board as the source of truth — not reachable from the hooks, a second source to reconcile.
- A hand-maintained status table — exactly the drift this ADR removes.

## Consequences

- Any session (new, compacted, another machine) resumes with the same next step from the same evidence.
- Re-running a step is safe: a passed gate is not redone because its evidence exists; artifacts are regenerated, not
  appended; approved artifacts are never overwritten.
- Commits on feature branches need trailers; humans committing by hand add them too (the hook says which).
